# motion-studio CLI: two-engine media seam, handoff and mix

Requires Node 22+, ffmpeg, ffprobe, and Chromium. Develop with Bun 1.4.0. Install with `npm install`, then run `npm run build`. For a packaged install, run `npm pack` and install the tarball in a project.

Commands:

- `init <slug>` creates `films/<slug>/` in the current directory with `assets/`, `shots/`, `stills/`, `renders/`, `audio/`, `critique/`, an empty valid `storyboard.json`, an empty `ledger.json` and a `BRIEF.md` with the XML sections inputs, direction, structure, build, gotchas and start. It never overwrites an existing folder.
- `validate <film-dir>` checks `storyboard.json` and `ledger.json` against `schema/storyboard.schema.json` and `schema/ledger.schema.json`, then checks cross-references: engine entrypoints exist, every asset id is in the ledger, every ledger file exists with the recorded SHA-256, shot ranges are half-open and contiguous from frame 0 to `meta.durationFrames`, each `cut` between shots falls on `audio.beatFrames` when a beat grid exists (handoff seams and shots with an `offBeatCut` reason are exempt), handoffs are declared on both sides of a seam, and still frames are inside their shot. It exits 1 and prints one `error:` line per problem. It also checks the vocabulary-controlled fields `shots[].camera`, `shots[].transition`, `shots[].effects[].term` and `critique[].worstIssues[].term` (D42): each must be a `motion-vocabulary` term id or `custom:<description>`. An unknown term or a bare `custom:` prints a `warning:` line and does not fail the project. `entry` and `exit` are schema fields (`cut` or `handoff`), not vocabulary. The term list is `dist/vocabulary.json`; `npm run build` generates it from `skills/motion-vocabulary/terms/*.md` and fails on a term entry without a definition or without an HF or Remotion recipe line.
- `status <film-dir>` prints each gate state (G1 to G5) and the next step. A stale gate shows why, for example `G1 stale (changed: BRIEF.md)` or `G2 stale (G1 not approved)`. On a film with cross-reference errors it adds a `validation: N errors` line and still exits 0; only a schema or JSON failure exits 1.
- `gate <film-dir> <G1-G5> <approve|changes|rescope> [--note <text>]...` records a decision in `storyboard.json`: the decision, the notes (appended), the round count and the SHA-256 of every current input of the gate. `changes` and `rescope` need at least one note. `changes` counts a note round; a fourth round is refused (3 per gate), so the user approves to accept, rescopes or stops. `rescope` resets the rounds and reopens the gate. `storyboard.json` must hold one record for each of G1 to G5 (in any order), and every earlier gate must be approved and not stale. A note or rescope marks every later gate that is not pending stale. `approve` copies what the gate showed (its freeze inputs: stills, animatic, full-pass master, delivery checks) to read-only files in `stills/approved/<gate>-<hash8>/`, where `hash8` is the first 8 hex of the SHA-256 of the recorded input hashes (sorted, as JSON). Only the schema must pass, so gates work on an unfinished film.

Gate inputs are data in `schema/gate-inputs.json` (D43). Each gate hashes its own inputs plus all earlier ones: G1 the brief, look-test stills (`stills/G1/`) and style bible with the `look` record; G2 adds the beat grid (`audio` fields `bpm`, `beatFrames`, `downbeatFrames`, `dropFrames`, plus `voice`, the files it names in `voice.script` and `voice.wordTimings`, and `beats.json`), the beat map (`meta.fps`, `meta.durationFrames`, and `id`, `startFrame`, `endFrame` of each shot) and stills (`stills/G2/`); G3 adds `animatic.mp4`; G4 adds the full-pass masters `renders/*/master.mkv`; G5 adds `shots/**` (without `shots/_look/` and engine output folders inside a shot: `snapshots/`, `renders/`, `beats/`, `out/`, `outputs/`, `build/`, `dist/`, `coverage/`), `ledger.json`, the whole `shots` and `audio` records (sound cues, assets, entrypoints, track), `meta.layouts` and the delivery checks in `renders/*/` (mix, final, drafts, sync, handoff, safe-zone and scan reports, poster, contact sheet). Shot descriptions, fill-mode `assets` and `soundCues`, and `meta.formats` do not stale G2; polish of shots and ledger after G4 stales only G5. Storyboard parts are hashed as canonical JSON under keys such as `storyboard.json#/voice`, or `storyboard.json#/shots{id,startFrame,endFrame}` for picked fields, so gate records never hash themselves. What a gate showed is bound as its frozen copy: once approved, that gate and every later gate hash the copy in `stills/approved/`, keyed by the live path, so a re-render or re-stitch never makes an approval stale. `node_modules`, hidden files and hidden folders are not hashed. An approval is stale when any input hash changed, an input appeared or disappeared, a frozen copy is missing, or it has no hashes. `validate` exits 1 with an `error:` line for each stale gate, recorded or by hash (D44). Render commands (`render`, `stitch`, `still`, `stills`, `sheet`, `handoff`, `mix`, `safezone`, `scan`) skip this gate check, because rerendering after an edit is how a film resumes.

- `beatmap <film-dir>` prints the beat map as a Markdown table, one row per shot, with a spoken-line column; see "Voice clock" below.
- `beats <film-dir>` proposes a beat grid from the `audio.track` file and writes the `audio` fields of `storyboard.json` with `grid: "detected"`. `beats <film-dir> --corrected <grid.json>` or `--imported <grid.json>` applies a grid from the creator instead. See "Beat grid" below.

- `doctor` reports whether this machine can run the pipeline: Node (22 or later), ffmpeg, ffprobe, HyperFrames, Chromium (the Chrome that `hyperframes doctor --json` finds; its update check is off), Remotion, the heygen CLI (0.3.0 or later, signed in by `heygen auth status`) and the image provider. It prints one line per item and exits 1 when a required tool (all but heygen and the image provider) is missing. heygen is not ready when `heygen auth status` exits 3 (no credential, or HeyGen refuses it), when the credential reports itself expired, or when the status cannot be checked. It installs, downloads and signs in nothing, and it never prints keys or account data: for heygen it shows only the credential type, its expiry and heygen's error code.
- `assets <film-dir> list | add | resolve` manages `ledger.json`; see "Asset ledger" below.

Expected failures (usage, invalid project, init refusal, media checks) print `error: <message>` lines without a stack trace.
- `render <film-dir>`, `stitch <film-dir>` and `still <film-dir> <shot-id> [local-frame]` read the shots from `storyboard.json`. They validate the project first and write nothing when it is invalid.
- `handoff <film-dir> [<shot-a> <shot-b>] [format]` checks every seam declared `exit: handoff`, or one explicit adjacent pair. `mix <film-dir> [format]` builds the master audio. Both need a successful `render` and `stitch`; see below.
- `safezone <film-dir> [format] [--shots <id,...>]` checks that held protected content stays inside each format's safe rectangle; see below.
- `stills` with shot ids and `safezone --shots` check the entrypoints of the named shots only, not of every shot. An engine builder checks its own shots this way while the other engine's shots do not exist yet. A `safezone --shots` run prints its checks and exit code but writes no `safezone.json`, because that report is the G5 delivery check of the whole film.
- `stills`, `animatic` and `sheet` make the board and review images; see "Board tooling" below.
- `scan <film-dir> [format]` flags glitches in each stitched master; `scan <video-file> [--report <file.json>]` scans any video for standalone critique. See "Glitch scan" below.

`render`, `stitch`, `handoff` and `mix` take an optional `[format]`: they work on that chosen format, or on every chosen format when none is named, because each format renders at its own canvas and a seam can pass in one format and fail in another. `still <film-dir> <shot-id> [local-frame] [format]` uses the primary format by default. Outputs live in `renders/<format>/`, where the folder name writes the colon as `x` (`16x9`, `9x16`, `1x1`), because a colon is not portable in file names. Shot outputs live in their own folder, `renders/<format>/shots/`, so a legal shot id such as `final`, `master` or `poster` never names a pipeline output:

| Path in `renders/<format>/` | Written by | Kind |
|---|---|---|
| `shots/<shot-id>.mkv` | `render` | intermediate: one video-only FFV1 Matroska clip per shot |
| `shots/<shot-id>.png` | `still` | review frame at the given zero-based shot-local frame (default 0), captured directly like `stills` |
| `render.json` | `render` | success marker: the format and the rendered shot ranges |
| `master.mkv` | `stitch` | intermediate: the video-only master picture (G4 shows it) |
| `handoff-<a>-<b>.json`, `.png` | `handoff` | delivery check: seam report and master strip |
| `mix.wav`, `final.mkv`, `sync.json` | `mix` | delivery: master audio, master picture with that audio, sync report |
| `safezone.json` | `safezone` | delivery check: safe-zone report |
| `contact-sheet-001.png`, ..., `transition-<a>-<b>.png`, `sheet.json` | `sheet` | review: 1 fps contact pages (G5 shows them), full-rate transition strips, tile index |

`stitch` checks the clips and joins them by stream copy. Matroska stores timestamps in milliseconds, and a clip's length is often not a whole number of milliseconds (7 frames at 30 fps is 233.33 ms), so plain concatenation lets the rounding add up across clips. `stitch` therefore sets the time of every master frame from its global frame index at the master fps; no frame is dropped or duplicated, and every frame is within half a millisecond of `index / fps`. `render` and `stitch` delete earlier handoff, mix and sheet outputs of that format, because those describe the previous master. `handoff` and `mix` read the master and clips of each format they work on.

The installed-CLI route from shots to delivery is `render` -> `stitch` -> `handoff` (when the film declares handoff seams) -> `mix`, each on `films/<slug>`. `render` and `stitch` make the intermediate clips and master; `handoff` and `mix` add the delivery files above. `safezone` runs on the shot sources and can run at any point. The all-manual fallback without the CLI is listed separately in the skill's `reference/v0-commands.md`.

`meta.layouts` gives each chosen format its canvas, safe rectangle and optional platform-overlay preset name. Both engines get the same layout inputs, so each format is reframed, not cropped or scaled from another format:

- Remotion gets the input props `{layout:{format, canvas:{width,height}, safe:{x,y,width,height}, overlay}}`. The composition must set its width and height from `layout.canvas` (for example with `calculateMetadata`); the CLI checks them.
- A Remotion shot may import `react`, `remotion` and `@remotion/transitions` (D54). The CLI bundles each shot with its own copies of these packages: a film lives outside the CLI, so the bundler searches the CLI's `node_modules` after the shot's own folders.
- HyperFrames gets the variables `format`, `canvasWidth`, `canvasHeight`, `safeX`, `safeY`, `safeWidth`, `safeHeight` and `overlay` (an empty string when there is none) through `--variables`. Declare them in `data-composition-variables` and read them with `window.__hyperframes.getVariables()`; each also reaches CSS as `var(--<id>)`. HyperFrames reads the canvas from the root's `data-width` and `data-height`, so the CLI renders a staged copy of `shots/<id>/` (a hidden `shots/.motion-<id>-*` folder at the same depth, removed afterwards) with those two attributes set to the format canvas.

`safezone` reads each shot's `protected` entries. An entry with `bounds: "measured"` names an element marked `data-protected="<id>"`. For each format the CLI renders the shot twice, normally and with only that element hidden by `opacity: 0` (a stylesheet rule with `!important`), and takes the bounds of the pixels that change at each held frame (D45). Opacity hides the whole element: a child cannot undo it, while a child can override `visibility: hidden` and stay painted. These are the painted bounds of the element, so wrapped text, logos and key UI are measured the same way in both engines. For content drawn inside a canvas or an SVG, `bounds` is instead a film-relative JSON file of declared geometry, `{"<format>": {"x","y","width","height"}}`. Only `heldFrames` are checked, so entrance and exit travel and unprotected full-bleed art never fail. A held element fails when its bounds leave the safe rectangle, when it paints no pixels (a missing or hidden `data-protected` element), or when its declared file has no rectangle for the format. `safezone` writes `renders/<format>/safezone.json` with every check, prints one line per check and exits 1 with one `error:` line per failure. The Remotion measurement bundles a small wrapper entry that applies the hide style. It lives in a hidden folder `shots/<id>/.motion-measure-<pid>/`, not in the author's `src/`, and is removed afterwards.

`fixtures/safezone/` is a three-format film (16:9 320x180, 9:16 180x320, 1:1 240x240) with one shot per engine. Each shot wraps a title to the safe width over full-bleed stripes and slides it in over frames 0 to 1. The Remotion shot adds an SVG mark with declared geometry. A `LIVE` label at 2,2 is marked `data-protected="corner"` for the failure test but is not protected in the fixture.

`handoff` decodes shot A's last frame and shot B's first frame through their color tags to RGB and area-averages each onto a fixed 32x32 cell grid. Two fixed thresholds apply to that pair: structure (the worst cell's mean absolute RGB difference, limit 0.15) and color (the largest per-channel change of the frame's mean color, limit 0.02); both run from 0 to 1. Stitch stream-copies lossless clips, so the two master frames at the seam must also be byte-identical to their shot frames; any difference is an encoded color jump. The same pair limits also apply across the cut in the master. For each seam it writes `handoff-<a>-<b>.json` (status `match`, `mismatch` or `encoded-color-jump`) and `handoff-<a>-<b>.png` (the two master frames at the seam). It prints one line per passing seam and exits 1 with one `error:` line per failing seam. It deletes the earlier reports it would write before it starts, so a failed run leaves no stale `match`.

A handoff compares frames for identity, so the moving element must land on a still pose at the seam: one frame of motion (about 2 px at 320x180) already exceeds the structure limit. The thresholds were tuned on one 320x180 fixture (engine rasterization noise 0.077, smallest real change measured 0.184). Recalibrate them when new formats, small text or thin lines give false results.

`mix` owns the film audio at 48 kHz stereo. It reads `audio.track`, the narration (`voice`, see "Voice clock" below) and every shot's `soundCues` from `storyboard.json` and their files from `ledger.json`. It trims or pads the track to the film. For each cue it finds the SFX's largest absolute sample and places it on the first sample of film frame `eventFrame + peakOffsetFrames` (`eventFrame` is a film frame inside the shot; `peakOffsetFrames` is the planned peak offset, usually 0). Lead-in before frame 0 and tails after the end are cut. The optional cue field `gainDb` (-60 to 24, default 0) changes that SFX's level before the sum. The sum gets one gain to reach -14 LUFS (ffmpeg `ebur128`). Then a true-peak limiter holds every peak at or below -1 dBTP (D53), for every film, so speech and SFX transients never clip or refuse the mix. It estimates true peaks with 4x oversampling, aims 0.3 dB below the ceiling, and ramps the gain down over 2 ms before a peak and back up over 50 ms after it (both channels together). Limiting lowers the loudness a little, so the gain is corrected and the limiter rerun until the loudness is within 0.1 LU of the target (at most 6 passes). The mix fails if the result is silent or shorter than 400 ms, measures outside -14 +/- 0.5 LUFS, or has a delivered true peak above -1 dBTP (then the sum is mostly peaks: lower the loudest cue with `gainDb` or re-level the narration). For each format it writes `mix.wav` (PCM 24-bit), `final.mkv` (that format's master video, stream-copied, with that audio) and `sync.json`. The sync report measures the delivered audio: integrated LUFS, true peak (`truePeakDbtp`), the limiter's ceiling and largest gain reduction (`limiter.maxGainReductionDb`, 0 when nothing was over; `mix` also prints it when above 0), and for each cue the frame of the loudest sample within 3 frames of its target and its offset from `eventFrame`. It also lists every cut seam with its nearest beat frame, the offset in frames and any `offBeatCut` reason, the narration (`voice`: asset, start frame, duck level and ducked spans in seconds, or `null`) and every spoken reveal with its word, the word's frame and the offset. A failed or refused mix removes earlier mix outputs.

`fixtures/handoff/` is a three-shot film: a Remotion title slides in and holds on the HyperFrames title's pose (a matching handoff), then the HyperFrames title hands off to a shot whose title starts higher (the intentional mismatch). `fixtures/two-engine/` cuts on the beat and places an SFX peak on the cut at frame 6. `fixtures/two-engine/audio/generate.sh` regenerates its audio with ffmpeg; the script lists their construction.

## Board tooling

`stills`, `animatic` and `sheet` need a structurally valid project, like the render commands.

- `stills <film-dir> [<shot-id>...] [--frames <n,...>] [--format <format>]` renders board stills through each shot's engine into `stills/G2/<format>/<shot-id>-f<frame>.png` (frame shot-local and zero-padded, for example `s01-f059.png`), where G2 hashes and freezes them. Without shot ids it renders every shot, without `--frames` each shot's `stillFrames`, and without `--format` every chosen format, each at its own canvas and layout inputs. A frame outside its shot is refused before anything renders. The new stills replace that shot's earlier stills in the format; a run over every shot also removes stills of shots that are no longer in the storyboard. Each run rebuilds `stills/G2/<format>/sheet.png`, the G2 contact sheet of every still in that folder (5 tiles per row in storyboard shot order, then frame order), and `sheet.json`, its tile index; G2 hashes both with the stills. The CLI makes no G1 look-test stills: those shots are not in the storyboard. Save the chosen look-test frames as `stills/G1/<look-id>.png`.
- `still <film-dir> <shot-id> [local-frame] [format]` captures one frame the same way into `renders/<format>/shots/<shot-id>.png`.
- `stills`, `still` and `render` refuse an engine frame with any transparent pixel and write nothing for it (D51): `error: transparent pixels in <shot-id> frame <n> (<format>): paint an opaque full-bleed background inside the composition root`. Clips and stills drop alpha, so a transparent pixel would show as black. In the PNG frames the CLI renders, a page (`html`, `body`) background and, in HyperFrames, the composition root's own background stay transparent; paint the background on a full-bleed element inside the composition (see the skill's engine contracts).

Still capture does not render, encode or check a whole clip. Remotion renders only the requested frames with `renderStill`. HyperFrames 0.8.81 has no frame-range render, and its `snapshot` command takes neither the composition file nor `--variables`, so it cannot get the format layout. The CLI therefore renders a HyperFrames shot once per format to PNG frames (no video encode and no clip check) and keeps the requested frames; revisit this when HyperFrames can render a frame range or snapshot with variables. Every still goes through the same RGBA-to-RGB conversion as a clip frame, and its size is checked against the format canvas. A still equals the rendered clip frame up to the rounding of the lossless clip encode.

`animatic <film-dir>` assembles the frozen G2 stills of the primary format (the copies in `stills/approved/G2-<hash8>/`, not the live files) into `animatic.mp4` at the film fps, which G3 shows. G2 must be approved and not stale. Each frame shows the nearest still of its shot: the picture switches at the midpoint between two consecutive stills, and an exact midpoint frame shows the later still. Every shot needs a still at its entry frame (0) and at its exit frame (its last frame); a missing one is refused. So the entry still starts on the shot's first frame, and the exit still holds for the second half of the last interval, up to the cut. For stills 0 and 5 of a 6-frame shot, frames 0 to 2 show the entry still and frames 3 to 5 the exit still. The audio is `audio.track`, cut or padded with silence to the film length (AAC, 48 kHz stereo); a film without a track gets a silent animatic, and narration (`voice`) is not added: mux it onto the animatic by hand. The video is H.264 (yuv420p, CRF 12), checked for frame count and size before it replaces the earlier animatic.

`sheet <film-dir> [format]` reads the stitched master of each selected format (after `render` and `stitch`) and writes review images into `renders/<format>/`: contact pages `contact-sheet-001.png`, ... of the frames at every whole second (frame 0, fps, 2 x fps, ...; 25 per page, 5 x 5, left to right, then top to bottom), one strip `transition-<a>-<b>.png` for each seam at the full frame rate (the first frame of shot b in the middle, 5 frames on each side, cut short at the film ends), and `sheet.json`, the index of each tile's global frame. Tiles are at most 320 pixels wide, with a 4-pixel margin and padding. A new run removes the earlier pages and strips first. G5 shows the contact pages (`renders/*/contact-sheet-*.png`). The `motion-critique` evidence packet uses the pages and strips.

## Voice clock

A narrated film uses two timing guides: the words of the narration for reveals and the beat grid for cuts.

- `voice` (optional) holds `script` (the script text file), `tts` (the ledger id of the narration audio, `null` until it exists), `wordTimings` and an optional `startFrame` (default 0), the film frame where the narration audio starts. The word-timing file is a JSON array of `{"text", "start", "end"}` in seconds from the start of the narration audio (the HyperFrames words-file shape; an `id` field is allowed and ignored).
- A word's film frame is `startFrame + round(start * fps)`, the same nearest-frame rule as beats (`secondsToFrame`).
- A shot's optional `reveals` list `{"word", "text", "frame"}`: the zero-based word index, the word's text and the film frame of the reveal. `validate` requires the text to match the file and the frame to be the word's film frame, inside the shot, and it names the right frame when one is off. So a new narration take with other timings fails `validate` until each reveal moves. A reveal without a `voice` is an error.
- `validate` also checks that the script and word-timing files are in the film, that the word list is well formed (non-empty text, `end >= start`, starts not decreasing) and that every word starts before the film ends. Cuts keep the beat-grid rule (D41); a word-timed cut needs `offBeatCut`.
- `beatmap <film-dir>` needs a schema-valid project and a readable word-timing file. Its columns are shot, frames (half-open), seconds, entry (`start`, `cut on beat`, `cut off beat[: reason]`, `cut` without a grid, or `handoff`), visual event (description), camera, spoken line (the words whose film frame falls inside the shot), reveals, sound cues and engine.
- `mix` places the narration audio from `startFrame`, cut at the film end. It ducks `audio.track` (not the SFX) by 12 dB during the spoken phrases: words less than 0.5 s apart form one phrase, and the level ramps linearly over 0.1 s before and after each phrase. The spans come from the word timings, not from the audio level. A film may have narration and no track. `mix` refuses a `voice` whose `tts` is `null`.

## Asset ledger

`assets` needs only a schema-valid project, because assets come before shots.

- `assets <film-dir> add <id> --file <path> --type <type> --source-kind <kind> --source <url-or-generator> --license <known|unknown|restricted> [--license-name <name>] --evidence <text> [--provider-asset-id <id>] [--shot <shot-id>]...` records a file from a website capture, stock, code, data or any other source kind. The file must be a regular file, not a symbolic link. A file inside the film folder is recorded in place, unless its real path leads outside the film; a file outside it is copied to `assets/<id><ext>` through a hidden temp file and a rename, so a crash never leaves a truncated asset file. The CLI adds the film-relative path and the SHA-256. A `known` license needs `--license-name`. For data, put the retrieval date and field in `--evidence`.
- `assets <film-dir> resolve <id> --provider <name> --type <type> --intent <text> [--voice-id <id>] [--shot <shot-id>]... [--paid-ok]` asks a provider for a file and records it with the provider's provenance. The provider writes into a hidden `.motion-assets-*` folder of the film; the CLI moves the file to `assets/<id><ext>`. A reply that names a symbolic link is refused. A missing provider is an error, never a switch to another source. When the provider can start paid generation for the type (every `image` provider call and HeyGen `voice`), the command refuses to run without `--paid-ok`. Pass it only after the creator agrees to the cost.
- `assets <film-dir> list` prints each entry (source, provider id, license and evidence, path, SHA-256, shots) with the file state `ok`, `missing`, `altered`, `outside the film folder` or `links outside the film folder`, then `unresolved rights:` with every `unknown` or `restricted` entry (D37).

Every new entry is checked against `schema/ledger.schema.json` before any file moves, and `ledger.json` is written through a temp file and a rename. So a refused entry or a provider failure leaves no ledger entry, no file under `assets/` and no staging folder. `validate` checks every ledger path and hash, and rejects a path whose real path (links followed) is outside the film folder.

The `heygen` provider imports HeyGen assets through `hyperframes media-use resolve`. Types: `bgm` and `sfx` (catalog `heygen.audio.sounds`), `image` and `icon` (catalog `heygen.asset.search`), all free catalog searches, and `voice` (HeyGen text to speech `heygen.tts`, paid, needs `--paid-ok`; the intent is the text to speak). A `voice` request needs `--voice-id <id>`, the chosen HeyGen voice (list them with `heygen voice list --engine starfish`); without it media-use would speak with the first voice HeyGen lists. The CLI passes it to media-use as `--voice-id` and records `speech: {voiceId, text}` in the ledger entry. `--voice-id` is refused for other types and by the image provider.

1. It runs `heygen --version` and `heygen auth status` first. An old CLI, a missing, refused or expired sign-in, or a status that cannot be checked stops the command before any search, with the reason and `run heygen auth login` where a login helps.
2. It runs media-use with the staging folder as its project and the HeyGen provider forced (`--provider`), so media-use does not reuse its caches, adopt files or fall back to another source. media-use still copies what it downloads into its global cache `~/.media/`.
3. It accepts only a record from the forced HeyGen provider, with a catalog id (`track_id` or `asset_id`; none for `voice`) and a regular file inside the staging `.media/` folder. It copies that file out, and the CLI freezes it as `assets/<id><ext>`.
4. The ledger entry has source kind `heygen`, the catalog id as `providerAssetId`, and license `unknown` with the provider and catalog id as evidence: the catalog reply states no license. `list` shows it under `unresolved rights` until the creator checks HeyGen's terms (D37).

`MOTION_STUDIO_MEDIA_USE` replaces `hyperframes media-use` with another command that takes the same arguments; the tests use it for an offline fake.

The image provider is a command named by `MOTION_STUDIO_IMAGE_PROVIDER` (source kind `ai-image`). The CLI ships no built-in paid provider. The command must support:

- `<command> ready`: exit 0 when it can work. It must not start paid work, because `doctor` runs it. Its output is not printed.
- `<command> resolve --type <type> --intent <text> --out <dir>`: write one file into `<dir>`, print `{"file":"<name in dir>","sourceUrlOrGenerator":"...","providerAssetId":"..." or null,"license":{"status":"known|unknown|restricted","name":"..." or null,"evidence":"..."}}` on stdout and exit 0. Any other exit, invalid JSON, a missing file or a path outside `<dir>` is a provider failure.

## Glitch scan

`scan <film-dir> [format]` reads the stitched master `renders/<format>/master.mkv` of one chosen format, or of every chosen format when none is named. It needs a successful `render` and `stitch` of that format. It writes `renders/<format>/scan.json` beside the master, prints one summary line per format, one `warning:` line per advisory flag and one `error:` line per blocking flag, and exits 1 when any flag blocks. The report records the master's SHA-256, so a reader can check that it describes the current master; `render` and `stitch` do not delete an old report. G5 binds `renders/*/scan.json` with the other delivery checks.

`scan <video-file> [--report <file.json>]` scans any video, for example a draft in standalone critique. It has no storyboard, so it knows no cuts, holds or effects: every finding is a defect, and a hard cut shows as an advisory color jump for the reviewer. The frame rate comes from the stream. The frame count is checked only when the container records one (Matroska does not). The report goes to `--report` when given.

Every frame is decoded once through its color tags to RGB and area-averaged onto a fixed 64x64 cell grid. Each flag has a frame (zero-based, on the film timeline), a length in frames, the shot and the shot-local frame, and its measures:

| Flag | Meaning | Severity |
|---|---|---|
| `frame-count` | The master does not decode to `meta.durationFrames` frames. | blocking |
| `blank` | A sudden flat dropout, or a shot that is flat from start to end (the engine rendered nothing). A flat frame is black, white or one color: every cell is within 0.02 of the frame's mean color. A flat run is sudden when it has content on both sides and the worst cell changes at least 0.1 into it and out of it. In standalone mode, a video that is flat from start to end is blank. | blocking |
| `flat` | Any other flat run: a flat opening or ending, a cut to a flat color, or a fade to or from one. | advisory |
| `pop` | One frame differs from both neighbors (worst cell change at least 0.1) while the neighbors match (their mean change is at most a quarter of the change into and out of the frame). A one-frame luma flash is also a pop when the frame before does not explain it as a brightness change: neither one gain and offset per channel (a uniform flash) nor a per-cell blend toward white or black (a glow, bloom or light leak) fits within 0.02 above the mean change between its neighbors. Such a frame is a wrong frame. | blocking |
| `cell-pop` | One cell changes at least 0.1 into a frame and out of it again, while that cell changes at most 0.02 between the frames on either side. This finds a small pop while the rest of the frame moves. A fast thin object can look the same, so cell pops less than 3 frames apart form one flag (a run with a `pops` count). | advisory |
| `stutter` | 1 or 2 repeated frames inside motion. A longer repeat is a hold and is not flagged. | advisory |
| `hitch` | One motion step is at least 2.5 times the median of the two steps on each side (skipped frames). | advisory |
| `flash` | The mean luma moves by at least 0.15 and returns to within 0.05 within 3 frames, and a one-frame flash is a brightness change of the frame before. | advisory |
| `color-jump` | A channel of the mean color steps by at least 0.04 and stays for the next 3 frames. | advisory |
| `ghost` | A frame is a blend (weight 0.2 to 0.8) of two different neighbors, for example a blended frame at a cut. | advisory |

A frame that is blank, flat, a flash, a pop, a cell pop or a ghost is one finding: the steps into and out of it do not also count as a stutter, hitch or color jump. Declared context turns a flag into `status: "context"` with the reason; context never blocks. A declared cut or handoff seam (the first frame of every shot after the first) explains a color jump, hitch or cell pop whose change crosses the seam. A repeated frame (stutter) that ends at the seam is context: the motion settles before the cut (an ease-out). A repeat that starts at or crosses the seam is context only at a handoff seam, where the motion continues; at a cut it is a doubled frame. A seam never explains a pop: a pop needs matching neighbors, which a cut never gives, so a pop at a seam is a wrong first or last frame of a shot. A blank frame, a flash and a blended frame are defects at a cut too, because a clean cut has none. A shot's `holds` (shot-local runs `{"start", "frames"}` where the picture is intentionally still) explain a stutter or hitch inside them. A shot's `effects` (`{"start", "frames", "term"}`, with a motion-vocabulary term or `custom:`) explain every flag inside the run. A flagged run is context only when it lies inside the declared run: a fault that starts inside an effect and continues past it stays a defect. An effect lies inside one shot, so it cannot span a seam. To cut to black across shots, make the black its own shot and declare an effect over it. A frame-count error is never context. `validate` checks that holds and effects end inside their shot.

The thresholds were calibrated on the 320x180 fixtures in `test/scan.test.ts`, which draw each defect frame by frame and encode it with ffmpeg: a clean film (a hard cut, a declared 2-frame hold, an undeclared 8-frame hold and fast motion with motion blur), and one variant for each flag. Known limits: a whole-frame pop is found only when the rest of the frame moves slowly, because the neighbors must match; during motion a small pop is only an advisory cell pop, and a small pop over a moving area is not found; an oscillating effect (a shake) looks like a pop on every frame and must be declared as an effect; a render fault that leaves the film's first or last frames flat is only an advisory `flat` run, so read the advisory flags (D47). A one-frame brightness change counts as an advisory `flash` when each 64x64 cell fits a blend of the frame before toward white or black, so a wrong frame in a grey palette, or a mostly white or mostly black wrong frame (for example an unstyled white HTML page), is only an advisory flash, not a blocking pop; read the advisory flags. Recalibrate on real engine renders when a flag is wrong.

## Beat grid

`beats` needs only a schema-valid project, because the grid comes before the shots and a new grid can move existing cuts off it. Every time in seconds becomes a frame with one rule, `round(seconds * fps)` (nearest frame, halves up; `src/frames.ts`). The product is first snapped to a millionth of a frame, so float error does not turn a half frame down: 0.58 s at 25 fps is frame 15. For example, 0.09 s at 30 fps is frame 3.

Detection decodes the track to mono 22.05 kHz PCM with ffmpeg and works in TypeScript:

1. Silence: a track whose peak is below -60 dBFS gives `grid: none (silent track ...)` and clears the grid (`grid`, `bpm` and `confidence` null, empty frame lists). A track without periodic onsets (speech, noise, a held tone) gives `grid: none (no periodic onsets ...)` in the same way. The command exits 0 in both cases; import a grid if the film needs one.
2. Onsets: every 2.9 ms, the RMS of the next 11.6 ms against the RMS of the 11.6 ms before it.
3. Tempo: the autocorrelation peak of the onset envelope between 70 and 180 BPM. Faster music is reported at half tempo and slower music at double tempo.
4. Beats: each beat is snapped to the strongest onset within 10 % of a period of its prediction, so the grid follows tempo drift. Beats are measured to about 3 ms. A true beat within 3 ms of a frame boundary can land on either frame.
5. Downbeats: meters 3 and 4 only. In the median bar the first beat must peak 1.25 times above the mean of the other beats. The best bar start must also score 1.2 times every other start in that meter. When both meters or neither fit, or accents repeat every 2 beats (kick on 1 and 3, snare on 2 and 4) so two bar starts fit, no downbeats are proposed and confidence is low.
6. Drops: a bar whose RMS is at least +6 dB above the two bars before it. The drop starts on a downbeat (on any beat without a meter). No such bar gives `drops: none`, never a guess.
7. Confidence is `high` only when at least 90 % of beats land on an onset, beat intervals vary by less than 5 % and the meter is clear. Each reason for `low` is printed.

Detection writes the proposal in seconds to `audio/beats.detected.json` (`{"bpm", "beats", "downbeats", "drops"}`) and does not replace a `corrected` or `imported` grid; set `audio.grid` to null to detect again. To correct it, edit a copy and run `beats <film-dir> --corrected <copy>`. A grid from another tool uses the same format with `--imported`. A user grid needs increasing, non-negative times, at least one beat, no two beats on one frame, and every downbeat and drop on a beat frame; each problem prints an `error:` line and nothing is written. A user grid gets confidence `high`.

The command prints `grid changed` or `grid unchanged` (tempo or any beat, downbeat or drop frame). G2 hashes the same four grid fields, so `grid changed` means G2 and every later approved gate are now stale (`status` shows them). `beats` writes `storyboard.json` through a temp file and a rename, like `gate`.

The bundled `hyperframes beats` utility was checked and not wrapped: it gives no downbeats or drops, reports its confidence only in a console line, needs Chrome and a HyperFrames project, and returns a constant-tempo grid from a rounded BPM that drifts over a long track.

The storyboard fields are described in `skills/motion-studio/reference/storyboard-schema.md` and defined by the JSON Schemas. `meta.fps` is 24, 25, 30 or 60. `meta.layouts` gives the width and height of each format. Each shot has `startFrame` and `endFrame` (half-open) and an `engine` (`remotion` or `hyperframes`). A HyperFrames `entrypoint` is an HTML file under `shots/<id>/`. A Remotion `entrypoint` is the composition id; its entry file is `shots/<id>/src/index.ts` or `src/index.tsx` and its public directory is `shots/<id>/public/`. Remotion composition dimensions, frame rate and duration must equal the format canvas, fps and shot range. HyperFrames compositions set their duration in HTML and carry `data-width` and `data-height` on the root, which the CLI sets per format. See `fixtures/two-engine/` for a working film folder.

Both engines produce PNG frame sequences, then ffmpeg encodes the same lossless FFV1/yuv444p/BT.709 intermediate. The CLI requires a successful render marker for stitching and invalidates it before every rerender. A failed rerender cannot stitch stale clips. A test-only `MOTION_STUDIO_CHILD_TIMEOUT_MS` overrides the 120-second subprocess timeout. The CLI verifies frame count, dimensions, color tags and ordered presentation timestamps in both clips and the stitched master. Matroska timestamps have millisecond precision, so checks allow 0.6 ms rounding error. Engine audio is not included. The fixture includes one OFL-licensed IBM Plex Sans local font, recorded in its ledger, and the same color patch in both compositions; the font license is in `fixtures/two-engine/assets/OFL.txt`.

Run `npm run typecheck` and `npm test` (it builds and packs first, then runs the suite under the Node and Bun test runners) for the process-level fixture checks under both Node and Bun. `test/beats.test.ts` builds its audio fixtures with ffmpeg `aevalsrc`, so each beat, downbeat and drop is known by construction. Remotion's company license is required for companies with more than three people.
