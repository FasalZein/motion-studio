# Remotion shot builder

Inputs: assigned Remotion shot ids, `storyboard.json`, approved frozen stills, the beat grid in `storyboard.json` `audio` (written by `motion-studio beats`; `beats.json` in the v0 manual flow), canonical ledger, format layouts, mode `keyframe`, `blocking` or `full`, and the [Remotion engine contract](../engines/remotion.md). Load only this engine's contract, the files on its allow-list and these `motion-direction` files: `reference/beat-contract.md`, `reference/seams-and-in-betweens.md`, `reference/living-holds.md` and `reference/choreography.md` for film shots, plus `reference/world-and-camera.md` in blocking mode (camera paths); `reference/world-and-camera.md`, `reference/seams-and-in-betweens.md`, `reference/living-holds.md` and `reference/choreography.md` for a look test. Add `reference/product-ui.md` for a shot with product UI, `reference/ui-kit.md` for a shot with built UI, `reference/polish.md` in full mode and `reference/2d-and-3d.md` for a shot that declares `threeD`.

Build motion, not poses. Every beat moves as its motion event and camera state; every hold is a living hold (camera drift, parallax, light, type or UI behavior keeps moving) that stays inside the D59 liveness limits in `reference/living-holds.md`. Real captures are hero material: move them with camera, masks, depth, 3D tilt and cuts on action; grey placeholder UI is a defect (D78). This engine builds every shot that shows built UI, from the film's UI kit (`reference/ui-kit.md`).

0. Before any shot uses built UI, build the UI kit as `reference/ui-kit.md` states: components themed from the brand tokens, a still per component and a behavior clip per behavior (typing, filtering, selection, expand), rendered with `motion-studio still` and `motion-studio render`. Fidelity check: compare each kit still side by side with a capture of the same brand screen or a designed reference frame (palette, type face and scale, radius, spacing, icons, content). Completion: every kit still has that comparison with no unexplained difference.
1. Build each assigned `shots/<id>/` project, or `shots/_look/<look-id>/` for a G1 look test, as the contract's **keyframe mode** states. Pin fonts and use props for each layout. A look test is a moving direction, not a pose: it reads the layout inputs as a shot does, holds one seam with motion on both sides and one type or UI beat, and stays inside the liveness limits; you choose its length. Keep a look test's assets in its own `public/`, so it renders unchanged when it is promoted to a shot one folder level up. It also receives its applied pattern replacements (`<template pattern> → <chosen move>`); build each chosen move, and use no other pattern from `motion-look`'s shared pattern list unless the brief states a reason. Completion: the contract's keyframe completion passes (for your film shots, `motion-studio stills films/<slug> <shot-ids>` and `motion-studio safezone films/<slug> --shots <shot-ids>` exit 0); for a look test, `motion-studio looktest films/<slug> <look-id>` exits 0, each listed replacement is visible in its clip and poster, and no unlisted template pattern appears without a stated reason.
2. In **blocking** mode (after G2), extend the approved keyframe component as the contract's **blocking mode** states: every beat moves with its real timing, camera path, seam thread and living holds at placeholder fidelity, in the approved layout; never start a new component or project for the shot. Completion: the contract's blocking completion passes for your shots (approved poses kept at the G2 still frames, every beat and hold moves, `safezone --shots` exits 0, `repro` for a `threeD` shot).
3. In **full** mode (after G3), extend the blocking component as the contract's **full mode** states; never start a new component or project for the shot. Then run the polish checklist in `reference/polish.md` for your shots. Completion: the contract's full-mode completion passes: each frozen approved still has a new still at the same local frame beside it, and each visible difference cites a named gate note.
4. Run `motion-studio safezone films/<slug> --shots <shot-ids>` over every chosen format. The render phase renders the film and runs the film-wide `safezone` after every builder finishes. Completion: the command exits 0, and the report gives the checks per format and the ledger ids used.
