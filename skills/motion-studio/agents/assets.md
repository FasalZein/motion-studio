# Asset phase

Inputs: `BRIEF.md`, `storyboard.json`, `ledger.json`, project root and mode `hero` or `fill`. Output: frozen files under `assets/`, updated canonical `ledger.json` and a rights-gap report.

0. Run `motion-studio doctor` first. It shows whether heygen is signed in and whether an image provider is configured; record each missing provider as a gap.
1. In **hero** mode, gather only the track or voice/script, real logo, local font files, palette and product screenshots needed for G1. For a product URL, `npx hyperframes capture <URL> -o <output>` captures site pixels and extracted tokens; verify the saved copy and source URL, then record it with `motion-studio assets <film> add <id> --file <copy> --source-kind website --source <URL> ...`. Record the original page's claims and retrieval date; do not treat inferred marketing copy as fact. Website capture command requires its installed CLI reference before use. Completion: the logo, one font file per font family, a palette hex list and at least one hero screenshot exist under `assets/`, each with a ledger id; the track or the voice script exists when the brief names one.
2. For HeyGen catalog music, SFX, images and icons, run `motion-studio assets <film> resolve <id> --provider heygen --type <bgm|sfx|image|icon> --intent "<need>" [--shot <id>]...`. It checks the heygen sign-in, resolves through `hyperframes media-use` with the HeyGen provider forced, freezes the file under `assets/` and records the catalog id. A missing or expired sign-in stops it with no entry: report the gap and use approved alternative sources. HeyGen `voice` is paid text to speech: ask the user first, and add `--paid-ok` only after they agree. It also needs `--voice-id <id>` (list voices with `heygen voice list --engine starfish`); the `--intent` is the exact text spoken, and the entry records both under `speech`. media-use returns no word timings: transcribe the frozen audio with `npx hyperframes transcribe <audio>` and check that the result is a `[{"text","start","end"}]` array before you set `voice.wordTimings`. Logo resolver uses official sources, not a HeyGen catalog logo guarantee. A resolved file is **not** proof of publishing rights: the entry's license is `unknown` until the user checks HeyGen's terms.
3. In **fill** mode, source real SFX for each event and measure peak offset; look for suitable stock on Mixkit or Pexels, and pin font files from Google Fonts with their license text. Make SVG/canvas/shader assets in code when they are a better fit. Use AI-generated stills only if a provider is available (`motion-studio assets <film> resolve <id> --provider image --type <type> --intent "<need>" --paid-ok`); the command refuses to run without `--paid-ok`, so ask the user before paid generation and add the flag only after they agree. For data stories, link every displayed value to the source URL, retrieved date and field (`--source-kind data`, date and field in `--evidence`). Record stock, code and data files with `motion-studio assets <film> add`. Completion: every used file has one ledger id and source evidence.
4. Each `ledger.json` entry records `{id,type,sourceKind,sourceUrlOrGenerator,providerAssetId,license:{status,name,evidence},localPath,sha256,shots}`. `sourceKind` is `heygen|website|stock|code|ai-image|data` (`video-model` is reserved). License `status` is `known|unknown|restricted`; a known license needs its name and evidence. Use `unknown` where catalog terms or source rights were not verified. On failure, add no partial entry; `motion-studio assets` refuses an invalid entry and writes nothing. Completion: `motion-studio validate` passes (every shot asset reference resolves to a hashed local file) and `motion-studio assets <film> list` shows the unknown/restricted rights for D37 before G5.
