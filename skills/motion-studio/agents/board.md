# Board phase

Inputs: approved `BRIEF.md`, hero ledger with the brand's sourced material, look choice, `storyboard.json` (with the `audio` beat grid), genre playbook, and `motion-vocabulary`. Load these `motion-direction` files: `reference/asset-first.md`, `reference/beat-contract.md`, `reference/idea-and-structure.md`, `reference/world-and-camera.md`, `reference/seams-and-in-betweens.md` and `reference/living-holds.md`; add `reference/product-ui.md` and `reference/ui-kit.md` for a product film and `reference/2d-and-3d.md` before declaring 3D. Output: `beatmap.md` in the film root, per-shot storyboard entries, requested local still frames.

`beatmap.md` holds four parts, which `node <this skill>/evals/check.mjs board films/<slug>` reads:

- `Hero shot: <shot-id>` on its own line.
- `## Sourced assets`: a table with columns `Ledger id`, `Role`, `Source URL`, `Capture date`; every id is in `ledger.json`. With no brand material, a line `No brand material: <reason>` instead.
- `## Beat contract`: a table with columns `Beat`, `Shot`, `Frames`, `Idea line`, `Motion event`, `Camera`, `Thread`, `In-between plan`, `Sound cue`, `Live content`, `Spoken line`, one row per beat. `Frames` starts `<start>-<end>`: film frames, end exclusive like shot ranges, optionally followed by the time. The beats cover `[0, meta.durationFrames)` in order without gaps, and each beat lies inside its shot.
- `## Engines`: a table with columns `Shot`, `Engine`, `Reason`, `UI source`, `3D`, one row per storyboard shot. `3D` is `no`, or `yes: <reason>` for a shot with `threeD`.

The eval fixture `evals/fixtures/board/beatmap.md` is a complete example.

0. Start from the brand's real material, as `reference/asset-first.md` states: source what is missing into the ledger, write the `## Sourced assets` table of `beatmap.md` (ledger id, role, source URL, capture date), and build the idea line and the motif from those ids. Real captures are hero material; grey placeholder UI is a defect. Completion: `beatmap.md` has the `## Sourced assets` table, or a `No brand material:` line with the reason; a board without either fails this check.
1. Analyze the real track. Run `motion-studio beats films/<slug>`: it writes BPM, beat, downbeat and drop frames and a confidence into `storyboard.json` `audio`, and the proposal in seconds to `audio/beats.detected.json`. Show the creator the result and each low-confidence reason. `grid: none` (silence or no beats), `downbeats: none` (ambiguous meter) and `drops: none` are answers, not gaps to fill by guessing. Invite corrections: edit a copy of the proposal and run `motion-studio beats films/<slug> --corrected <file>`; a grid from a DAW or another tool goes in with `--imported <file>`. With voice, keep word timing and beats separate: set `voice.wordTimings` to the TTS or transcribe words file (`[{"text","start","end"}]`, seconds from the start of the narration audio) and `voice.startFrame` to the film frame where the audio starts. Time reveals to words and cuts to beats. If no track, import a voice-led manual grid. Seconds become frames with `round(seconds * fps)`. Without the CLI, use `npx hyperframes beats <hyperframes-project> --json` for beats and BPM only and record downbeats and drops by hand. Completion: `audio.grid` is `detected` with the creator's approval, `corrected` or `imported`, and word timing sources are explicit.
2. Write the `## Beat contract` table of `beatmap.md`, one row per beat: idea line, frames (with time), motion event, camera start and end, thread, in-between plan, sound cue and live content, plus the spoken line; the engine goes in the `## Engines` table. A motion event names what moves from where to where, with which easing or spring; every hold inside a beat is a living hold and names its live content. Put each shot's motion events and camera poses in its `description`. For every seam, name its thread: what carries from one shot into the next. The `Thread` cell of the beat that opens a seam names that shot's thread kind. Set `thread` on each shot after the first to `{"kind": <thread id from motion-vocabulary terms/threads.md or custom:<description>>, "shared": <the carried thing in words>}`, for example `{"kind": "shared-element-thread", "shared": "the blue search field"}`. Once the shots are in `storyboard.json`, print it with `motion-studio beatmap films/<slug>`: one row per shot, with the thread (`missing` when a seam has none), the spoken line (the words whose frame falls in the shot), reveals and sound cues. For each spoken reveal, add `{"word", "text", "frame"}` to the shot's `reveals`, where `frame` is `voice.startFrame + round(start * fps)` of that word; `motion-studio validate` names the right frame when one is off. Name camera, transition and timing moves in `motion-vocabulary` terms; prefix genuinely new terms with `custom:`. Use the chosen playbook's timing bounds and evidence requirements. Completion: every beat has a motion event and live content for its holds, and every seam has a thread (`motion-studio validate` names each seam without one).
3. Partition the timeline into gap-free half-open shots. Select Remotion for shots that show built UI (the UI kit, `reference/ui-kit.md`) and other React/component-led shots; select HyperFrames for kinetic type, moved captures, HTML/GSAP and catalog motion (registry motion code adapted into the shot's own layout, D55) (D78). Record **why** per shot in the `## Engines` table of `beatmap.md`, and name each product shot's UI source there: a capture ledger id or a UI kit component (`none` for a shot without UI). A shot uses 3D only when the look allows it and the board declares it: set `"threeD": {"reason": <why 3D serves the idea or world>}` on that shot (D65). An engine switch is a seam like any other: carry its thread through a `handoff` that `motion-studio handoff` checks, or through a threaded cut with motion on both sides. Assign entry, exit and local still frames: the start and end pose of each beat, plus entry and final in-range frame. For a beat `<start>-<end>` in a shot that starts at film frame `S`, the start pose is local frame `start - S` and the end pose is local frame `end - 1 - S`. Stills show poses for review; the moving animatic and the liveness report judge the motion. The G3 animatic is the stitched blocking renders, so the beat timing in the storyboard, not the still frames, sets how long each pose holds. Completion: every shot's range, engine, entrypoint, asset ids and still-frame requests are defined in `storyboard.json`, and the `## Engines` table records the engine reason.
4. For each `handoff` seam, write the seam pose and seam motion in both shots' `description`: canvas color, each shared element's position, size and colors on shot B's first frame, and its velocity (direction and pixels per frame). Motion continues through a handoff: shot A's motion continues one frame past its end, and that frame equals shot B's first frame, so B starts one frame of motion after A's last frame and moves on at the same velocity. The CLI `handoff` check renders that frame of A and compares it with B's first frame; an element that stops at the seam fails it. Completion: every `handoff` seam has the same written seam pose and velocity in both shot descriptions.
5. Add a `protected` entry for each text, logo or UI element whose held bounds must fit the safe rectangle, with its layout inputs. Completion: every shot that shows text, a logo or UI has at least one `protected` entry.
6. Name the hero shot that carries the G1 look test in the `Hero shot:` line; `motion-studio` promotes the chosen `shots/_look/<look-id>/` source into it. Completion: `beatmap.md` names the hero shot id.
7. Dispatch keyframe builders for the chosen engines; each checks only its own shots. After every builder finishes, run `motion-studio safezone films/<slug>` (every shot, every format; it writes `renders/<format>/safezone.json`) and return failures to the owning builder. Then render real stills for all formats at the `stillFrames` of every shot: `motion-studio stills films/<slug>`. It writes `stills/G2/<format>/<shot-id>-f<NNN>.png` (NNN: the shot-local frame zero-padded to 3 digits, for example `s03-f070.png`) and rebuilds each format's contact sheet `stills/G2/<format>/sheet.png` with its tile index `sheet.json`. Rerun it for named shots after a keyframe change (`motion-studio stills films/<slug> <shot-id>`). Without the CLI, render the frames with the engine commands in `reference/v0-commands.md` into the same paths and tile the sheet by hand. Present G2 as [reference/g2.md](../reference/g2.md) states. Completion: `motion-studio validate films/<slug>` exits 0 and `node <this skill>/evals/check.mjs board films/<slug>` prints `board ok`.
8. After G2 approval, dispatch blocking builders for the chosen engines; each extends its approved keyframe source and checks only its own shots against the engine contract's blocking completion. After every builder finishes, run the render phase's G3 step: render and stitch the primary format and run `motion-studio animatic films/<slug>`. Return each still span its liveness advice names to the owning builder before G3 when the fix is cheap. Present G3 as [reference/g3.md](../reference/g3.md) states. Completion: `animatic.mp4` exists from the current blocking renders, and its liveness advice is ready to present with it at G3.
