# Board phase

Inputs: approved `BRIEF.md`, hero ledger, look choice, `storyboard.json` (with the `audio` beat grid), genre playbook, and `motion-vocabulary`. Load these `motion-direction` files: `reference/beat-contract.md`, `reference/idea-and-structure.md`, `reference/world-and-camera.md`, `reference/seams-and-in-betweens.md` and `reference/living-holds.md`; add `reference/product-ui.md` for a product film and `reference/2d-and-3d.md` before declaring 3D. Output: beat map, per-shot storyboard entries, requested local still frames.

1. Analyze the real track. Run `motion-studio beats films/<slug>`: it writes BPM, beat, downbeat and drop frames and a confidence into `storyboard.json` `audio`, and the proposal in seconds to `audio/beats.detected.json`. Show the creator the result and each low-confidence reason. `grid: none` (silence or no beats), `downbeats: none` (ambiguous meter) and `drops: none` are answers, not gaps to fill by guessing. Invite corrections: edit a copy of the proposal and run `motion-studio beats films/<slug> --corrected <file>`; a grid from a DAW or another tool goes in with `--imported <file>`. With voice, keep word timing and beats separate: set `voice.wordTimings` to the TTS or transcribe words file (`[{"text","start","end"}]`, seconds from the start of the narration audio) and `voice.startFrame` to the film frame where the audio starts. Time reveals to words and cuts to beats. If no track, import a voice-led manual grid. Seconds become frames with `round(seconds * fps)`. Without the CLI, use `npx hyperframes beats <hyperframes-project> --json` for beats and BPM only and record downbeats and drops by hand. Completion: `audio.grid` is `detected` with the creator's approval, `corrected` or `imported`, and word timing sources are explicit.
2. Write the beat map as the beat contract table, one row per beat: idea line, frames (with time), motion event, camera start and end, thread, in-between plan, sound cue and live content, plus spoken line and engine. A motion event names what moves from where to where, with which easing or spring; every hold inside a beat is a living hold and names its live content. Put each shot's motion events and camera poses in its `description`. For every seam, name its thread: what carries from one shot into the next. Set `thread` on each shot after the first to `{"kind": <thread id from motion-vocabulary terms/threads.md or custom:<description>>, "shared": <the carried thing in words>}`, for example `{"kind": "shared-element-thread", "shared": "the blue search field"}`. Once the shots are in `storyboard.json`, print it with `motion-studio beatmap films/<slug>`: one row per shot, with the thread (`missing` when a seam has none), the spoken line (the words whose frame falls in the shot), reveals and sound cues. For each spoken reveal, add `{"word", "text", "frame"}` to the shot's `reveals`, where `frame` is `voice.startFrame + round(start * fps)` of that word; `motion-studio validate` names the right frame when one is off. Name camera, transition and timing moves in `motion-vocabulary` terms; prefix genuinely new terms with `custom:`. Use the chosen playbook's timing bounds and evidence requirements. Completion: every beat has a motion event and live content for its holds, and every seam has a thread (`motion-studio validate` names each seam without one).
3. Partition the timeline into gap-free half-open shots. Select HyperFrames for HTML/GSAP or catalog motion (registry motion code adapted into the shot's own layout, D55); select Remotion for React/component-led shots. Record **why** per shot in the beat map. A shot uses 3D only when the look allows it and the board declares it: set `"threeD": {"reason": <why 3D serves the idea or world>}` on that shot (D65). An engine switch is a seam like any other: carry its thread through a `handoff` that `motion-studio handoff` checks, or through a threaded cut with motion on both sides. Assign entry, exit and local still frames: the start and end pose of each beat, plus entry and final in-range frame. Stills show poses for review; the moving animatic and the liveness report judge the motion. The G3 animatic shows on each frame the nearest still of the shot, switching at the midpoint between two stills, so still frames set how long each pose holds. Completion: every shot's range, engine, entrypoint, asset ids and still-frame requests are defined in `storyboard.json`, and the beat map records the engine reason.
4. For each `handoff` seam, write the seam pose and seam motion in both shots' `description`: canvas color, each shared element's position, size and colors on shot B's first frame, and its velocity (direction and pixels per frame). Motion continues through a handoff: shot A's motion continues one frame past its end, and that frame equals shot B's first frame, so B starts one frame of motion after A's last frame and moves on at the same velocity. The CLI `handoff` check renders that frame of A and compares it with B's first frame; an element that stops at the seam fails it. Completion: every `handoff` seam has the same written seam pose and velocity in both shot descriptions.
5. Add a `protected` entry for each text, logo or UI element whose held bounds must fit the safe rectangle, with its layout inputs. Completion: every shot that shows text, a logo or UI has at least one `protected` entry.
6. Name the hero shot that carries the G1 look test; `motion-studio` promotes the chosen `shots/_look/<look-id>/` source into it. Completion: the beat map names the hero shot id.
7. Dispatch keyframe builders for the chosen engines; each checks only its own shots. After every builder finishes, run `motion-studio safezone films/<slug>` (every shot, every format; it writes `renders/<format>/safezone.json`) and return failures to the owning builder. Then render real stills for all formats at the `stillFrames` of every shot: `motion-studio stills films/<slug>`. It writes `stills/G2/<format>/<shot-id>-f<frame>.png` and rebuilds each format's contact sheet `stills/G2/<format>/sheet.png` with its tile index `sheet.json`. Rerun it for named shots after a keyframe change (`motion-studio stills films/<slug> <shot-id>`). Without the CLI, render the frames with the engine commands in `reference/v0-commands.md` into the same paths and tile the sheet by hand. At G2 present the beat contract table with its thread column and the start and end stills of each beat, not just a text plan, with the primary format's contact sheet. Completion: the beat map and engine-rendered G2 still paths are ready for a gate decision.
