# Storyboard v0

`storyboard.json` is the machine source of truth. Version `0` uses the field names below. The CLI JSON Schemas `cli/schema/storyboard.schema.json` and `cli/schema/ledger.schema.json` define every field; `motion-studio validate films/<slug>` checks them (CLI #4). Frames are integers. Convert seconds by `round(seconds * fps)`.

- `meta`: `fps` is 24, 25, 30 or 60. `layouts` is required (CLI #9; it replaces the earlier `meta.canvas`). It maps each chosen format (primary and extra, no others) to `{canvas:{width,height}, safe:{x,y,width,height}, overlay}`. The canvas must match the format's aspect ratio, and the safe rectangle must lie inside the canvas. `overlay` is an optional platform-overlay preset name or `null`; engines receive it, the CLI does not interpret it. `init` writes 16:9 at 1920x1080 with the safe rectangle 96,54 1728x972. Move an older `meta.canvas` into `meta.layouts[<primary>].canvas`. An empty project uses `null` for `meta.genre`, `look.id`, `audio.track`, `audio.grid`, `audio.bpm` and `audio.confidence` until the brief and beat phases set them.
- `shots[]` ranges are half-open `[startFrame, endFrame)` and cover `[0, meta.durationFrames)` without gaps or overlap. `stillFrames` are **shot-local**.
- `shots[].entrypoint`: for HyperFrames, an HTML file under `shots/<id>/`. For Remotion, the composition id; its project entry file is `shots/<id>/src/index.ts` or `src/index.tsx`, and its public files live in `shots/<id>/public/`.
- `shots[].entry`/`exit` are `cut` or `handoff`, and both sides of a seam must agree (the previous shot's `exit` equals this shot's `entry`). The first shot cannot enter by handoff and the last shot cannot exit by handoff.
- `shots[].camera` and the optional `shots[].transition` hold a `motion-vocabulary` term id, or `custom:<description>`. `transition` names the move at the shot's entry (D42).
- `shots[].thread` (D64) names what the seam into the shot carries: `{"kind": <thread id>, "shared": <text>}`. Every shot after the first needs one; the first shot has no seam before it. `kind` is a `motion-vocabulary` thread id (`terms/threads.md`: `shared-element-thread`, `shape-match-thread`, `movement-match-thread`, `camera-direction-thread`, `light-thread`, `sound-thread`, `beat-cut-thread`) or `custom:<description>`; `shared` names the carried thing in words and is not empty. `validate` and the render commands reject a missing thread, another kind or an empty `shared`. `beatmap` prints a thread column. A thread edit does not stale G2 (D43).
- `shots[].threeD` (optional, D65): `{"reason": <text>}`, the board's declaration that the shot uses 3D and why 3D serves the idea or the world. Declare it only when the look allows 3D. `validate` rejects shot sources that import three.js, `@react-three/fiber` or `@remotion/three` without it (D66).
- When `audio.beatFrames` is not empty, every `cut` between shots must be a beat frame (D41). Handoff seams are exempt. For an intentional off-beat cut, set `offBeatCut` on the later shot to a non-empty reason, for example `"word-timed reveal"`. The critique packet lists these cuts separately.
- `shots[].soundCues[]` (CLI #3): `eventFrame` is a film frame inside the owning shot. `peakOffsetFrames` is the planned distance from the event to the SFX peak (0 puts the peak on the event, negative before it). The optional `gainDb` (-60 to 24, default 0) sets the SFX level before the mix is normalized. `mix` limits true peaks to -1 dBTP, so a loud SFX is held there instead of clipping; lower it with `gainDb` when `sync.json` shows a large `limiter.maxGainReductionDb`. `audio.track` and each cue `asset` are ledger ids; `mix` reads their files from the ledger.
- `voice` (optional, CLI #19): `script` is the script text file, `tts` the ledger id of the narration audio (`null` until it exists; `mix` refuses `null`), `wordTimings` a JSON array of `{"text","start","end"}` words in seconds from the start of that audio (the words file of HyperFrames TTS or transcribe; an extra `id` is allowed). The optional `startFrame` (default 0) is the film frame where the audio starts. A word's film frame is `startFrame + round(start * fps)`. Every word must start before the film ends.
- `shots[].reveals[]` (optional): spoken reveals, `{"word": <zero-based index in wordTimings>, "text": <that word's text>, "frame": <film frame>}`. `validate` requires `text` to match the file and `frame` to be the word's film frame, inside the shot. A reveal needs a `voice`. Cuts still follow the beat grid; a word-timed cut needs `offBeatCut`.
- `shots[].protected` entries name elements whose held bounds must fit each layout's safe rectangle. `id` uses the shot id pattern and matches the element's `data-protected` attribute in both engines. `bounds` is `"measured"` (`safezone` measures the painted pixels, D45) or a film-relative JSON file of declared geometry for canvas or SVG content, `{"<format>": {"x","y","width","height"}}`. `heldFrames` are shot-local frames inside the shot; list only frames where the element is held, not entrance or exit travel.
- Optional `shots[].holds` and `shots[].effects` are declared context for `scan`. Each is a list of shot-local runs `{"start", "frames"}` inside the shot. A `holds` run marks frames where the picture is intentionally still, so repeated frames there are not a stutter; it does not exempt the film from the liveness limits (D59), and a hold in the beat contract is a living hold, not a `holds` run. An effect adds `term` (a `motion-vocabulary` term or `custom:<description>`) and marks an intended flash, strobe, glitch, blank or shake, so no flag that lies inside it counts as a defect. A flag that runs past the declared run stays a defect. An effect cannot span a seam; to cut to black across shots, make the black its own shot with an effect.
- `gates` lists `G1` to `G5` in this order. `inputHashes` map project-relative gate input paths to SHA-256 hex strings; a part of `storyboard.json` uses a key such as `storyboard.json#/voice`, or `storyboard.json#/shots{id,startFrame,endFrame}` for picked fields, and is hashed as canonical JSON. `motion-studio gate` writes them (CLI #5). Gate `decision` records the user's actual words or structured choice, not an inferred approval. An optional `waiver` (`{"check": "liveness", "reason"}`) records a G4 approval the director gave without a passing liveness report (D60); `motion-studio gate` writes it and drops it on the next decision.
- `critique[].worstIssues` holds at most 3 items, each `{shot, frame, term, issue, repair}`.
- `ledger.json` is `{"version":"0","assets":[...]}`; each entry has the fields in the assets brief. Every license needs non-empty evidence; a `known` license also needs a name. `localPath` is film-relative and `sha256` must match the file.

The example is illustrative: replace hash placeholders with real hashes before any approval; add ledger entries for every named asset. `voice` may be `null`; `audio.track` may be `null` when voice drives the film. `dropFrames` is empty when no drop exists. `confidence` can be `low`. Genres: `product-launch`, `ui-morph-loop`, `explainer`, `showreel`, `social-kinetic-type`. Gates use `pending`, `approved`, `changes`, or `stale`. Only record scores backed by reviewer evidence; mark other dimensions unverified.

`validate` rejects a missing or unknown engine, a missing entrypoint, an asset id not in the ledger, a ledger file that is missing, outside the film folder (also through a symbolic link) or has the wrong hash, a gap or overlap in the half-open ranges, shots that do not cover `durationFrames`, an off-grid cut without `offBeatCut`, an unmatched handoff, a seam without a valid thread, shot sources that read a wall clock, a frame loop or `Math.random`, load a script or asset from the network, or import three.js without `threeD` (D66), a still frame outside its shot and an fps other than 24, 25, 30 or 60. `status films/<slug>` prints each gate state and the next step; on an unfinished film it also prints the number of validation errors instead of failing.

Completion: all shots cover the timeline, every path and asset id resolves, and gate approvals carry real hashes.
