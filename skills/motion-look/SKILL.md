# Motion Look

Use this skill alone for a look choice or style bible, or load it from `motion-studio` for G1 and taste updates. The look describes visual direction, not genre timing or engine commands. Load the `motion-vocabulary` skill for exact term ids and recipes. Use the genre playbook for timing. For product UI inside a shot, use its product design rules.

1. **Read direction.** Collect the logline, genre, formats, source URL, real logo, type, palette and references. For a recommendation, read `~/.motion-studio/taste.json` using [taste-profile.md](reference/taste-profile.md). Give a liked entry with a relevant note more weight than an untested entry; explain a conflict with the product. Done when the proposed direction names its source assets and relevant liked or rejected entries, or states that the profile is empty.
2. **Select and adapt.** Read the relevant [look files](looks/) and [shared patterns](patterns.md). A look file is a starting direction, not a fixed brand kit: its palette, free fonts and nearest HyperFrames preset are examples. Pin local Google Fonts files, and copy no preset brand values into a verified product identity. Its motion signature ids are `motion-vocabulary` term ids. Its look-specific pattern pair applies in addition to every shared pair. Propose 2 or 3 distinct candidates for G1, or one for a standalone selection. For each candidate, set **both** named variation axes to concrete product-specific values, replace palette/type with verified brand assets where appropriate, and name the signature move and one focal object. Done when each candidate has two recorded axis values and a reason tied to this product rather than a generic mood.
3. **Extract references when supplied.** For each local video, extract frames at 2 fps with ffmpeg and make a labeled contact sheet. For a frame or image folder, make a labeled sheet from the supplied images. Use the method and fields in [style-bible-template.md](reference/style-bible-template.md). Analyze order, transitions, camera, type, palette, material and hierarchy; record **take** and **do not take** for each source. Save `films/<slug>/style-bible.md` in a film project; in standalone mode, save it at the agreed output path. Done when every source has its own take/do-not-take lines, and the style bible maps the useful visual method to this product without copying its subject.
4. **Prepare G1.** Give the orchestrator a build brief for 2 or 3 candidates: real frozen logo, type and palette assets; hero content and claim; both axis values; frame dimensions; a keyframe pose; and the **applied pattern replacements** for that candidate. List each pair from [shared patterns](patterns.md) and the look file as `<template pattern> → <chosen move>`, and give a stated reason for any pattern the candidate keeps on purpose. Each candidate is a look test, not a film shot: build it at `shots/_look/<look-id>/` and render its still to `stills/G1/<look-id>.png`. The orchestrator dispatches a keyframe-mode build per candidate and renders **one hero still each**. In an inline fallback, run builds sequentially and label any self-review non-independent. Render candidate stills with the engine commands in the candidate folder, not the CLI: `motion-studio still` selects a storyboard shot id, and a look test is never in `storyboard.json`. HyperFrames: `npx hyperframes check --at <local-seconds> --snapshots`, then copy the snapshot frame to `stills/G1/<look-id>.png`. Remotion: `npx remotion still <composition-id> ../../../stills/G1/<look-id>.png --frame=<local-frame>`. Follow the `motion-studio` skill's engine contracts for each engine's flags and checks. Present the filled brief, stills and reference take/do-not-take lines at G1. Done when all 2 or 3 stills exist as real engine renders using product assets, each still shows its listed pattern replacements, and the user can choose from the images rather than names alone.
5. **Record taste and freeze direction.** At G1, write the chosen look as liked, with a note that quotes the director's decision. Before you record a passed candidate as a rejected look, check its still against its applied pattern replacements. If the still honored them, record the look as rejected. If the still kept a shared or look-specific pattern without a stated reason, the director passed on the execution, not the look: add a `notes` entry that quotes the decision and names the pattern, and do not add the look to `rejected`. Record the selected axes and style-bible path in the project look record. Copy the current global taste file to `films/<slug>/taste-snapshot.json` and point the project at that snapshot; later global changes never silently change this film. At every gate note, append its text and any named `motion-vocabulary` terms. At final acceptance, record the look, signature moves and pacing profile. Follow [taste-profile.md](reference/taste-profile.md) for the JSON shape and read/write points. v0 edits the JSON and project record directly (CLI: `motion-studio gate`, #5). Done when the global profile holds only observed decisions, the snapshot is a valid copy, and the project points to it.

If G1 changes the brief or look, hand the change to the `motion-studio` gate flow; that skill owns revision binding, resets and round caps. For standalone use, stop after the requested look, style bible or profile update. Keep reference rights and any unverified brand facts explicit.
